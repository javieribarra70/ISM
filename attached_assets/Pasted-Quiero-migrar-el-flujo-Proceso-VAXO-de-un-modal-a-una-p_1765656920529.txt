Quiero migrar el flujo “Proceso VAXO” de un modal a una página dedicada. El bug actual es que el modal no aparece cuando ya existen relaciones; no quiero más parches sobre Radix Dialog, quiero cambio estructural.

Objetivo final

Al presionar el botón “VAXO” en ConnectionTab, en lugar de abrir un modal, navegará a una nueva ruta:

/projects/:projectId/vaxo

Esa página mostrará el wizard completo del proceso VAXO (antes ISMProcess) sin depender de tabs/modals.

Debe funcionar tanto si hay relaciones existentes como si no.

PASO 1: Crear ruta y página nueva (sin tocar lógica todavía)

Crear archivo: client/src/pages/vaxo-page.tsx

Debe leer projectId desde la URL (Wouter).

Debe renderizar un placeholder por ahora: “VAXO page for project X”.

Ejemplo:

import { useRoute } from "wouter";

export default function VaxoPage() {
  const [match, params] = useRoute("/projects/:projectId/vaxo");
  const projectId = params?.projectId;
  return <div>VAXO page for project {projectId}</div>;
}


Registrar ruta en el router principal (donde se declaran las rutas en app).

Agregar:

<Route path="/projects/:projectId/vaxo" component={VaxoPage} />

No avanzar si la ruta no funciona.

Actualmente client/src/components/ism/ism-process.tsx mezcla Dialog + wizard.

Crear componente nuevo: client/src/components/ism/vaxo-wizard.tsx

Mover ahí todo lo que sea:

etapas del proceso

preguntas

carga de relaciones existentes

matrices / niveles / diagrama

El nuevo componente NO debe usar <Dialog> ni overlay.

Props mínimas:

type VaxoWizardProps = {

En ism-process.tsx, reemplazar el contenido por:

Dialog + <VaxoWizard ... />

Ejemplo:

<VaxoWizard projectId={projectIdFromContext} preselectedIdeaIds={...} />


No modificar el algoritmo ni matrix-utils.ts.

En client/src/components/tabs/connection-tab.tsx:

Importar useLocation de Wouter.

const [, setLocation] = useLocation();

const handleStartProcess = () => {

Dejar el toast informativo si hay relaciones, pero NO debe controlar el flujo.
